# 2026-09-15

## Changed

- Implemented FR6 (`updateNowPlayingInfo`/`configureRemoteCommands`) in
  `PlaybackEngine`, and decided where `AVAudioSession` category
  configuration/activation belongs:
  - `refreshNowPlayingInfo()` publishes the full Now Playing dictionary
    on every `PlaybackEvent`, guarded by a discontinuity check (compares
    `currentTime` against where it *should* be given the last published
    rate and a timestamp, rather than raw inequality) so ordinary
    continuous ticking during playback doesn't defeat the dedup the way
    a naive comparison would.
  - `configureRemoteCommands()` registers play/pause/seek directly
    against `MPRemoteCommandCenter.shared()`.
  - `activateAudioSession()` sets category + activates in one call, from
    `load(_:)` and from interruption-end recovery; `deactivateAudioSession()`
    runs only from `stop()`, not on every item replacement.
- Added `PlaybackError.audioSessionUnavailable`, and an additive
  `PlaybackError.category` (`.content`/`.network`/`.systemResource`/
  `.cancelled`) for display/telemetry grouping — not a statement about
  retry behavior, since every `PlaybackError` a caller sees is already
  Tier 2 terminal (`error-handling-strategy.md`).
- Added an iOS-only `os.Logger` — every previously-silent `try?` around
  `AVAudioSession` now logs its error instead.
- Added a `deinit` to `PlaybackEngine` that removes outstanding
  `NotificationCenter` observers if the engine is deallocated without
  `stop()` having run first.
- `MPMediaItemArtwork`'s size-request closure now resizes to whatever
  the system actually asks for, instead of always returning the
  original image.
- Added 4 tests to `PlaybackEngineTests` (10 → 14) covering Now Playing
  publish/clear behavior against the real `MPNowPlayingInfoCenter`
  singleton (safe to read/write directly in tests, unlike
  `MPRemoteCommandCenter`'s target registrations).

## Decisions

- No injectable seam over `MPRemoteCommandCenter` (a `RemoteCommandTarget`
  protocol was built, then deliberately removed) — registering against
  the real singleton and accepting that slice as manually/integration-tested
  was judged better than carrying a protocol + fake whose only reason to
  exist would be testability, not the feature itself.
- Now Playing info clearing was redesigned twice this session. First cut:
  a separate `clearNowPlayingInfo()` awaited directly in `stop()` — this
  had a real reentrancy race (a `load(_:)` landing during that `await`
  could have its fresh publish overwritten by the stale clear). Fixed by
  collapsing to one writer: `refreshNowPlayingInfo()`'s existing
  `nil`-`currentMediaItem` branch handles the clear, distinguishing
  `.idle`/`.failed` ("truly nothing loaded," clear) from `.loading`
  ("mid-`load(_:)`, don't flash-clear") via `stateMachine.state`, and
  `clearNowPlayingInfo()` itself re-checks `currentMediaItem == nil`
  right before writing.
- `AVAudioSession` deactivation moved out of `teardownCurrentSession()`
  (shared by `load(_:)` and `stop()`) into `stop()` alone — the previous
  behavior deactivated-then-immediately-reactivated the session on every
  single track change, which repeatedly signalled other apps to un-duck
  and re-duck (`.notifyOthersOnDeactivation`), an audible glitch in
  whatever else was playing.
- `configureAudioSessionCategory()` was removed as a separate function/
  `init`-time `Task`; its `setCategory` call was folded into
  `activateAudioSession()` itself. The two were previously independent
  fire-and-forget `Task`s with no ordering guarantee, so a `load(_:)`
  called immediately after construction could activate under the wrong
  (previous/default) category. One call site removes the race
  structurally instead of synchronizing around it.
- `AVAudioSession.interruptionNotification` observation moved from
  per-item (`startObserving(_:)`/`teardownCurrentSession()`) to
  once-per-engine-lifetime (`init`) — a `load(_:)` that failed before
  building a player previously left the app with no interruption
  observer at all, unable to notice even if the conflict cleared.

## Known limitations

- Moving the interruption observer to engine-lifetime does not add
  automatic retry of a `load(_:)` that failed on session contention —
  the state machine has no "pending load" concept, and building one was
  judged out of proportion for this pass. A session conflict at
  load-time is a permanent `.failed(.audioSessionUnavailable)`; the same
  conflict happening mid-playback recovers automatically.
- No `removeTarget` on `PlaybackEngine` deallocation for
  `MPRemoteCommandCenter` targets — mitigated by wiping all targets
  before re-registering in `configureRemoteCommands()`, so at most one
  live target per command exists regardless of how many engine instances
  have existed, but a genuinely idle period with zero live engines still
  has stale (harmless, `[weak self]`-guarded) targets registered until
  the next instance's `init` runs.
- Remote command wiring (play/pause/seek actually reaching
  `MPRemoteCommandCenter.shared()`) and `AVAudioSession` behavior remain
  untested by `swift test` — both depend on real system state that isn't
  mockable without a seam already judged not worth carrying. Verified
  this session via `xcodebuild build`/`clean build` against an iOS
  Simulator SDK for every `#if os(iOS)` path touched, and by re-reading
  the resulting control flow against `error-handling-strategy.md` and
  `concurrency-model.md`, not by dedicated tests.
