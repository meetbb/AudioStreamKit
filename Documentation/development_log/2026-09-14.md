# 2026-09-14

## Changed
- Added a revalidation policy to `MediaSource`: a cache hit now
  opportunistically re-probes the origin for a changed ETag/Last-Modified
  before answering `contentInformationRequest`, invalidating and
  refetching on a mismatch, and falling back to the existing cache
  entry if the origin is unreachable or never gave a validator.
- Added `MediaItem` (public struct: url + optional title/artist/artwork).
- Implemented most of `PlaybackEngine`: `load`, `play`, `pause`, `stop`,
  `seek`, `currentTime`, `duration`, and the AVFoundation-facing signal
  handlers (item status/time-control-status KVO, item-ended and audio
  session interruption notifications), all funneled through a single
  `apply(_:)` into `PlaybackStateMachine` and out onto the `states`
  stream.
- Added `MediaSourceDelegate` so `MediaSource.fetchWithRetry` can report
  its stall/recovery/retry-exhaustion lifecycle outward — this is what
  makes `.stalled`/`.retryBudgetExhausted` real states instead of
  unreachable ones. `PlaybackEngine` sets itself as the delegate right
  after constructing `MediaSource`.
- Added `Tests/AudioStreamKitTests/Playback/PlaybackEngineTests.swift`
  (10 tests) covering the parts of `PlaybackEngine` that don't need a
  live network: the unsupported-scheme failure path, and every command's
  "ignored event" behavior before/without a loaded item.

## Decisions
- `MediaSource` reports its retry lifecycle via a delegate protocol
  (`weak var` on `MediaSource`, set post-init by `PlaybackEngine`), not
  closures passed at construction — closures can't capture `PlaybackEngine`
  as `self` while it's still being constructed, since `MediaSource` is
  built as a default parameter value in `PlaybackEngine.init`.
- Cache revalidation is opportunistic, not strict: an unreachable origin
  serves the existing cache rather than failing, since strict validation
  before every cached play would defeat "plays with no network."

## Known limitations
- `PlaybackEngine`'s interruption handling (`handleAudioSessionInterruption`)
  only compiles on iOS — `AVAudioSession` is unavailable on macOS, which
  this package also targets. Caught by running the test suite against an
  iOS Simulator (`xcodebuild test`), not just `swift test` (macOS-only
  here) — also caught a real Swift 6 data-race bug in that same function
  (a non-`Sendable` `Notification` was being captured across a `Task`
  boundary; fixed by decoding it into plain `Sendable` values first).
- Nothing yet configures or activates the app's `AVAudioSession` category
  (e.g. `.playback`) — interruption notifications can still arrive without
  it, but the app isn't properly declaring itself as an audio-playback app.
- `updateNowPlayingInfo`/`configureRemoteCommands` (FR6) are still
  unimplemented stubs.
- Most of `PlaybackEngine`'s real-AVPlayer logic (resuming from `.paused`,
  cancelling a genuine `.stalled` retry, the KVO/notification handlers
  actually firing, a real seek) isn't unit tested — needs a resolvable
  asset or local server, same gap already noted for `MediaSource`.
