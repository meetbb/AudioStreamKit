# 2026-09-17

## Changed

- Added an internal `AudioPlayer` initializer that accepts a pre-built
  `PlaybackEngine`, so tests can substitute a test-backed engine instead of
  going through the public init's real `MediaCache`/`MediaSource` stack. No
  public API change.
- Built a local, in-process HTTP test server and a synthetic audio fixture,
  used to write real integration tests for `PlaybackEngine` and `AudioPlayer`
  against an actual asset and network stack instead of a live remote URL.
- Found and fixed a real playback bug while writing those tests: starting
  playback while a track was still loading recorded the intent but never
  told the real player to start once the track became ready, so playback
  could get stuck indefinitely.

## Decisions

- Hand-rolled the HTTP test server instead of adding a third-party
  dependency, since only a small, deliberately limited feature set was
  needed.

## Known limitations

- None of today's session's known limitations remain open — `AudioPlayer`
  now has test coverage, and `PlaybackEngine`'s previously-untested
  load/play/seek paths against a real asset are covered too.
